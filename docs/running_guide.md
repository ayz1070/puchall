# 러닝 측정 기능 구현 지침

## 목표

Flutter 앱에서 스마트폰 센서를 활용해 러닝 기록 기능을 구현한다.

측정 항목은 다음과 같다.

* 총거리
* 현재 속도
* 평균 속도
* 평균 페이스
* 운동 시간
* 이동 시간
* 걸음 수
* 케이던스
* 예상 칼로리
* 현재 운동 상태

## 사용 데이터

* GPS 위치
* 운영체제 걸음 수 센서
* 가속도 센서
* 사용자 체중

GPS를 주요 데이터로 사용하고, 걸음 수와 가속도는 GPS 데이터 검증과 운동 상태 판단에 사용한다.

## GPS 처리

GPS 위치를 1~3초 간격으로 수집한다.

이전 좌표와 현재 좌표 사이의 거리를 계산해 총거리에 누적한다.

다음 위치 데이터는 제외한다.

* 정확도가 지나치게 낮은 위치
* 1~2m 이하의 미세 이동
* 비정상적으로 높은 순간 속도
* 이전 위치에서 갑자기 크게 벗어난 좌표

현재 속도는 구간 거리와 경과 시간으로 계산한다.

```text
현재 속도 = 구간 거리 ÷ 경과 시간
평균 속도 = 총거리 ÷ 이동 시간
평균 페이스 = 운동 시간 ÷ 거리
```

현재 속도와 페이스는 최근 3~5초 평균 또는 지수 이동 평균을 적용해 평활화한다.

## 걸음 수 처리

Android의 Step Counter 또는 iOS의 CMPedometer 등 운영체제 기능을 우선 사용한다.

최근 10초 동안 증가한 걸음 수로 케이던스를 계산한다.

```text
케이던스 = 최근 10초 걸음 수 × 6
```

걸음 수는 다음 용도로 사용한다.

* 실제 이동 여부 확인
* 정지와 러닝 구분
* GPS 좌표 튐 검증
* 차량 이동 구분
* GPS 음영 구간 거리 보완

## 가속도 처리

가속도 X, Y, Z 값을 이용해 합성 가속도를 계산한다.

```text
magnitude = sqrt(x² + y² + z²)
```

중력 성분을 제거한 뒤 최근 1~3초 동안의 변화량과 반복 패턴을 계산한다.

가속도는 다음 판단에 사용한다.

* 스마트폰 정지 여부
* 반복적인 러닝 충격 존재 여부
* 단순히 스마트폰만 흔든 상황
* 걸음 센서와 실제 움직임의 일치 여부

가속도 값을 직접 거리 계산에 사용하지 않는다.

## 운동 상태 분류

운동 상태를 다음 네 가지로 구분한다.

```dart
enum MotionState {
  stationary,
  walking,
  running,
  vehicle,
}
```

초기 판단 기준은 다음과 같다.

| 상태  | 초기 기준                              |
| --- | ---------------------------------- |
| 정지  | 속도 1km/h 미만, 걸음 없음, 가속도 변화 작음      |
| 걷기  | 속도 1~7km/h, 케이던스 60~140            |
| 달리기 | 속도 6km/h 이상, 케이던스 140 이상, 반복 충격 존재 |
| 차량  | 속도 20km/h 이상, 걸음 없음, 러닝 패턴 없음      |

한 번의 값으로 상태를 변경하지 않는다.

* 상태 변경 조건이 3~5초 지속되면 상태 변경
* 차량 판단도 일정 시간 연속 조건을 만족할 때 적용

임계값은 상수로 분리해 향후 실제 데이터에 맞게 조정할 수 있도록 한다.

## 자동 일시정지

다음 조건이 5초 이상 지속되면 자동 일시정지한다.

```text
GPS 속도 낮음
+ 걸음 수 증가 없음
+ 가속도 변화 작음
```

다음 조건이 2~3초 이상 지속되면 자동으로 재시작한다.

```text
걸음 수 증가
+ 반복적인 가속도 변화
+ GPS 이동 확인
```

전체 운동 시간과 실제 이동 시간을 별도로 관리한다.

## GPS 오류 검증

다음 상황은 GPS 좌표 튐으로 판단해 거리에 포함하지 않는다.

```text
GPS 위치만 크게 이동
+ 걸음 증가 없음
+ 가속도 변화 없음
```

다음 조건에서는 실제 이동 가능성이 높은 것으로 판단한다.

```text
GPS 위치가 연속적으로 이동
+ 걸음 수 증가
+ 반복적인 가속도 변화
```

걸음 센서가 일시적으로 누락될 수 있으므로 최근 몇 초간의 데이터 전체를 기준으로 판단한다.

## GPS 음영 구간

GPS가 잠시 끊긴 경우 걸음 수와 사용자 평균 보폭으로 임시 거리를 계산한다.

```text
추정 거리 = 걸음 수 × 사용자 평균 보폭
```

사용자 평균 보폭은 GPS가 정상인 구간에서 계산한다.

```text
평균 보폭 = GPS 이동 거리 ÷ 해당 구간 걸음 수
```

GPS가 복구되면 GPS 값을 우선한다.

걸음 기반 거리는 짧은 GPS 음영 구간에서만 사용하며 장시간 누적하지 않는다.

## 칼로리

초기 버전에서는 다음 식을 사용한다.

```text
예상 칼로리 = 사용자 체중(kg) × 러닝 거리(km)
```

예:

```text
70kg × 5km = 약 350kcal
```

칼로리는 직접 측정값이 아닌 예상값으로 표시한다.

향후에는 평균 속도, 운동 시간, MET, 심박수 데이터를 추가해 개선할 수 있도록 계산 로직을 별도 클래스로 분리한다.


## 권장 처리 구조

```text
GPS 위치 수신
→ GPS 정확도와 좌표 튐 검사
→ 구간 거리 계산
→ 걸음 수와 케이던스 계산
→ 가속도 활동량 계산
→ 운동 상태 분류
→ 자동 일시정지 처리
→ 유효한 러닝 구간만 거리 누적
→ 속도와 페이스 평활화
→ 칼로리 계산
→ 상태 업데이트 및 저장
```

## 구현 원칙

* GPS를 거리와 속도 계산의 기준으로 사용한다.
* 걸음 수와 가속도는 GPS 검증과 상태 분류에 사용한다.
* 센서 원본 데이터를 UI에서 직접 처리하지 않는다.
* 센서 수집, 필터링, 상태 판단, 통계 계산을 각각 분리한다.
* 모든 임계값은 설정 파일 또는 상수 클래스로 관리한다.
* 실제 러닝 데이터를 로그로 저장해 임계값을 조정할 수 있도록 한다.
* Android와 iOS의 센서 권한 및 백그라운드 실행 차이를 고려한다.
* 초기 구현은 단순한 임계값 기반으로 만들고 이후 실제 데이터로 보정한다.
