# 워킹 측정 기능 적용 전략

## 목표

Flutter 앱에서 스마트폰 센서를 활용해 걷기 운동 기록 기능을 구현한다.

측정 항목은 다음과 같다.

* 총거리
* 현재 속도
* 평균 속도
* 평균 페이스
* 운동 시간
* 이동 시간
* 걸음 수
* 케이던스
* 평균 보폭
* 예상 칼로리
* 현재 운동 상태

## 기본 전략

워킹은 러닝보다 이동 속도가 느려 GPS 좌표 오차가 실제 이동 거리보다 크게 나타날 수 있다.

따라서 다음 우선순위를 사용한다.

```text
1. 걸음 센서로 실제 보행 여부 판단
2. GPS로 이동 경로와 거리 측정
3. 보폭으로 GPS 거리 보완
4. 가속도로 걸음 패턴과 정지 상태 검증
```

GPS만으로 거리를 계산하지 않고 걸음 수, GPS, 가속도 데이터를 함께 사용한다.

## GPS 처리

GPS 위치를 약 2~5초 간격으로 수집한다.

이전 위치와 현재 위치 사이의 거리를 계산하되 다음 값은 제외한다.

* GPS 정확도가 지나치게 낮은 위치
* 짧은 시간에 비정상적으로 멀리 이동한 위치
* 걸음이 없는데 발생한 미세 좌표 이동
* 차량 속도에 가까운 위치 변화
* 이전 경로와 크게 벗어난 좌표

워킹은 속도가 느리므로 1~2m의 이동을 무조건 제외하면 실제 걸음 거리가 누락될 수 있다.

따라서 짧은 GPS 이동은 바로 버리지 않고 최근 몇 초 동안의 걸음 수와 함께 판단한다.

```text
GPS 이동 거리 작음
+ 걸음 수 증가
+ 가속도 반복 패턴 존재
→ 실제 걷기로 판단

GPS 이동 거리 작음
+ 걸음 수 증가 없음
+ 가속도 변화 작음
→ GPS 흔들림으로 판단
```

## 걸음 수 처리

Android의 Step Counter 또는 iOS의 CMPedometer와 같은 운영체제 걸음 감지 기능을 우선 사용한다.

운동 시작 시점의 누적 걸음 수를 기준값으로 저장한다.

```text
운동 걸음 수
= 현재 시스템 걸음 수 - 운동 시작 시점 걸음 수
```

최근 10초 또는 20초 동안 증가한 걸음 수를 기준으로 케이던스를 계산한다.

```text
케이던스
= 최근 10초 걸음 수 × 6
```

예:

```text
최근 10초 동안 18걸음
→ 108걸음/분
```

걸음 수는 다음 목적으로 사용한다.

* 실제 보행 여부 확인
* 자동 일시정지 판단
* GPS 좌표 흔들림 검증
* GPS 음영 구간의 거리 계산
* 평균 보폭 계산
* 걷기 속도와 운동 강도 판단

## 평균 보폭 계산

초기 보폭은 사용자의 키를 기준으로 추정할 수 있다.

```text
초기 걷기 보폭
≈ 키 × 0.40~0.43
```

예:

```text
키 175cm
175 × 0.415
≈ 72.6cm
```

이 값은 임시값으로만 사용하고, GPS가 정상인 구간에서 사용자별 보폭을 보정한다.

```text
사용자 보폭
= 유효한 GPS 거리 ÷ 같은 구간 걸음 수
```

예:

```text
GPS 거리: 500m
걸음 수: 680걸음

평균 보폭
= 500 ÷ 680
≈ 0.735m
```

한 번의 기록으로 보폭을 확정하지 않고 여러 운동 기록의 평균을 사용한다.

```text
새 보폭
= 기존 보폭 × 0.8
+ 이번 운동 보폭 × 0.2
```

비정상적인 보폭은 제외한다.

예:

```text
0.3m 미만
또는
1.3m 초과
→ 계산에서 제외
```

## 거리 계산

GPS가 정상인 경우 GPS 거리를 기본값으로 사용한다.

```text
GPS 정확도 양호
+ 걸음 증가
+ 걷기 패턴 존재
→ GPS 거리 누적
```

GPS가 불안정하거나 잠시 끊긴 경우 걸음 수와 보폭을 사용한다.

```text
보행 거리
= 걸음 수 × 평균 보폭
```

최종 거리는 다음처럼 처리한다.

```text
GPS 정상 구간
→ GPS 거리 사용

GPS 불량 구간
→ 걸음 수 × 보폭 사용

GPS 복구 구간
→ 중복 거리가 발생하지 않도록 구간 분리
```

GPS 거리와 보폭 거리를 동시에 더하지 않는다.

## 가속도 처리

가속도 X, Y, Z축으로 합성 가속도를 계산한다.

```text
합성 가속도
= sqrt(x² + y² + z²)
```

가속도는 거리 계산이 아니라 다음 판단에 사용한다.

* 실제 걸음 패턴 존재 여부
* 정지 여부
* 스마트폰을 손으로 흔든 상황
* 차량이나 자전거 이동
* 운영체제 걸음 센서의 오검출 검증

걷기에서는 달리기보다 충격이 작으므로 단순 임계값보다 반복 패턴을 중심으로 판단한다.

```text
낮거나 중간 정도의 가속도 변화
+ 일정한 반복 주기
+ 걸음 수 증가
→ 정상 걷기
```

다음 상황은 걸음 오검출 가능성이 있다.

```text
걸음 수 증가
+ GPS 이동 없음
+ 가속도 패턴 불규칙
+ 짧은 시간에 과도한 걸음 발생
→ 스마트폰 흔들기 또는 오검출 후보
```

## 상태 분류

운동 상태를 다음과 같이 분류한다.

```dart
enum WalkingMotionState {
  stationary,
  walking,
  fastWalking,
  running,
  vehicle,
}
```

초기 기준은 다음과 같이 설정한다.

| 상태    | 초기 기준                           |
| ----- | ------------------------------- |
| 정지    | 속도 0.8km/h 미만, 걸음 없음, 가속도 변화 작음 |
| 걷기    | 속도 1~5.5km/h, 케이던스 약 60~120     |
| 빠른 걷기 | 속도 4.5~7km/h, 케이던스 약 110~150    |
| 달리기   | 속도 7km/h 이상, 높은 케이던스와 충격 패턴     |
| 차량    | 속도 15~20km/h 이상, 걸음 없음          |

이 기준은 고정값이 아니며 실제 사용자 데이터를 기준으로 조정한다.

한 번의 센서값으로 상태를 변경하지 않고 3~5초 이상 조건이 지속될 때 변경한다.

## 자동 일시정지

다음 조건이 5~10초 지속되면 자동 일시정지한다.

```text
걸음 수 증가 없음
+ GPS 속도 낮음
+ 가속도 변화 작음
```

워킹은 신호 대기나 잠깐 멈추는 경우가 많으므로 러닝보다 자동 일시정지 시간을 길게 설정한다.

권장 초기값:

```text
자동 일시정지: 정지 상태 7초 지속
자동 재시작: 걸음 상태 3초 지속
```

자동 재시작은 다음 조건을 사용한다.

```text
걸음 수 연속 증가
+ 반복적인 가속도 패턴
+ GPS 이동 또는 보폭 거리 발생
```

## 속도 계산

현재 속도는 짧은 GPS 구간 하나로 계산하지 않는다.

워킹은 저속이므로 GPS 오차의 영향을 줄이기 위해 최근 5~10초 또는 최근 10~20m 구간을 기준으로 계산한다.

```text
현재 속도
= 최근 유효 거리 ÷ 해당 구간 시간
```

속도는 이동 평균 또는 지수 이동 평균으로 평활화한다.

```text
표시 속도
= 이전 속도 × 0.8
+ 새 속도 × 0.2
```

러닝보다 더 낮은 가중치를 사용해 화면 흔들림을 줄인다.

## 평균 속도와 페이스

```text
평균 속도
= 총거리 ÷ 실제 이동 시간
```

```text
평균 페이스
= 실제 이동 시간 ÷ 총거리
```

워킹에서는 `분/km`와 함께 `km/h`를 모두 표시하는 것이 이해하기 쉽다.

예:

```text
평균 속도: 5.1km/h
평균 페이스: 11분 46초/km
```

## 칼로리 계산

초기에는 체중과 거리 기반으로 계산한다.

```text
걷기 칼로리
≈ 체중(kg) × 거리(km) × 계수
```

초기 계수는 운동 강도에 따라 다음처럼 적용할 수 있다.

```text
느린 걷기: 0.4
보통 걷기: 0.5
빠른 걷기: 0.6
```

예:

```text
70kg 사용자가 5km 보통 속도로 걸음

70 × 5 × 0.5
= 약 175kcal
```

운동 상태와 평균 속도를 이용해 계수를 선택한다.

```text
평균 속도 4km/h 미만
→ 0.4

평균 속도 4~5.5km/h
→ 0.5

평균 속도 5.5km/h 이상
→ 0.6
```

칼로리는 측정값이 아니라 예상값으로 표시한다.

## 차량 이동 제외

다음 조건이면 차량이나 자전거 이동으로 판단한다.

```text
GPS 속도 높음
+ 걸음 수 증가 없음
+ 걷기 가속도 패턴 없음
```

예:

```text
속도 25km/h
걸음 수 증가 없음
→ 걷기 거리에서 제외
```

버스나 차량 안에서 스마트폰이 흔들려 걸음이 일부 증가할 수 있으므로 속도 조건을 함께 사용한다.

## 최종 처리 흐름

```text
GPS 위치 수신
→ GPS 정확도 검사
→ 걸음 수 증가량 계산
→ 케이던스 계산
→ 가속도 반복 패턴 검사
→ 정지·걷기·빠른 걷기·달리기·차량 분류
→ GPS 거리 또는 보폭 거리 선택
→ 유효 거리 누적
→ 자동 일시정지 처리
→ 속도와 페이스 평활화
→ 칼로리 계산
→ 운동 기록 저장
```

## 초기 권장 설정

```text
GPS 수집 주기: 2~5초
걸음 분석 구간: 최근 10초
가속도 분석 구간: 최근 2~3초
속도 평활화 구간: 최근 5~10초
자동 일시정지: 정지 7초 지속
자동 재시작: 보행 3초 지속
GPS 불량 시: 걸음 수 × 사용자 보폭
차량 후보: 15~20km/h 이상 + 걸음 없음
```

## 핵심 원칙

* GPS를 이동 경로와 기본 거리 측정에 사용한다.
* 걸음 수를 실제 보행 여부 판단의 핵심 데이터로 사용한다.
* GPS가 불안정하면 걸음 수와 사용자 보폭으로 거리를 보완한다.
* 가속도는 걷기 패턴과 정지 여부 검증에 사용한다.
* GPS 거리와 보폭 거리를 중복 누적하지 않는다.
* 워킹은 저속 운동이므로 러닝보다 긴 시간 범위로 속도를 평활화한다.
* 보폭과 임계값은 실제 운동 기록을 바탕으로 사용자별 보정한다.
